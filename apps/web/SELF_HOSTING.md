# TripLedger 首版：Sites 與自架

這是手機優先、同時支援桌面的首版內測網頁。原本 `apps/api`、`apps/mobile` 保留不動；新版位於 `apps/web`。

## 已實作

- 使用 ChatGPT 登入；網站入口可公開，帳本由建立者及核准的成員共同使用。財務旅伴與登入帳號分開保存，沒有帳號的旅伴仍可參與分攤。
- 「共同記帳」建立 7 天有效、單次使用且可撤銷的邀請連結；持連結者登入後申請，管理者核准角色與旅伴綁定後才能讀取帳務及收據。
- 管理者管理成員、全部帳務及備份；記帳成員新增支出並更正／作廢自己建立的支出；僅檢視成員唯讀。移除成員立即停止後續 API 存取，保留歷史與餘額。
- 啟用共同記帳後，新還款先待確認，收款方確認後才計入餘額；收款旅伴未綁定帳號時，管理者可代辦並留下操作紀錄。既有單人版還款維持已確認。
- 建立單幣別旅程、平均／指定金額分攤、收據上傳、部分或完整還款、作廢紀錄。
- 同一筆支出可由多位旅伴共同付款，在「誰先付款」新增／移除付款人並填各自金額；實際付款與應分攤金額分開記錄，付款合計須等於支出總額。
- 支出更正保留修改前後內容及時間；旅程與既有旅伴改名、封存／解除封存保留歷史。封存旅程唯讀，仍可備份。
- 支出名稱／付款旅伴搜尋、分類／日期／有效或作廢或已更正篩選，篩選不改變帳本總額。
- 新增與更正表單遇到版本衝突會保留輸入，核對最新帳務後才能重送；另一分頁封存旅程時不切換草稿的目標旅程。
- 收據支援選檔、拍照入口與預覽；超過 1 MiB 的 JPG／PNG／WebP 會嘗試縮小為 JPEG，最終上傳檔案須小於等於 1 MiB。
- 整數最小貨幣單位計算；TWD/USD/EUR/HKD 為兩位小數，JPY 為整數。均分尾差按保存的旅伴順序分配。
- 條件版本更新避免兩個分頁互相覆蓋；同一新增操作 ID 重送不會重複記帳。
- 每旅程 JSON 完整備份／匯入，包括作廢紀錄與收據 bytes、MIME、大小和 SHA-256。
- 相同 React 介面及業務邏輯可在獨立 Node.js 服務運行，改用 SQLite 和本機收據檔。

內測範圍：每位建立者最多 50 個旅程、每旅程 2–20 位財務旅伴、20 個有效帳號綁定、300 筆支出、200 筆還款、300 筆更正／作廢／旅程異動歷史；旅程 document 上限 1 MiB ＋ 64 KiB，涵蓋舊付款欄位及歷史快照的升級增量。邀請與待核准申請各最多 20 筆；累積成員歷史接近上限時停止新邀請與核准，預留移除成員的容量。達上限時拒絕新異動，不刪除舊帳務歷史；封存時預留解除封存的名額與容量。每張收據 1 MiB、旅程收據合計 8 MiB、匯入 JSON 最大 14 MiB。旅伴人數與幣別固定，管理者可修改既有旅伴名稱；更正時保留原收據，收據替換另行規劃。目前沒有跨幣別換算、離線記帳、OCR、付款、訂閱或購買權益。帳本記錄款項與還款申報，不會執行轉帳。

目前匯出備份 schema 5，包含旅伴更名歷史、各付款人金額、封存狀態、原始及更正後資料、操作人、成員歷史、還款狀態與確認／取消歷程；仍接受 schema 1、2、3、4 備份。舊單付款人資料及歷史快照會轉為同一人全額付款，原分攤與餘額保持。舊資料沒有保存均分／指定模式，匯入或首次更正採原有分攤金額，不自動重新分配。歷史快照不重複儲存收據，匯入重新配置收據 ID 時不影響歷史。備份不包含平台 subject、有效帳號綁定、邀請密鑰／雜湊、申請者 email 或登入 session。schema 5 備份須使用本版或更新版本還原；不可退回不支援多人付款的舊程式繼續寫入。

## 頁面與網址

新增或更正支出時，先填「支出總額」，再於「誰先付款」按「新增付款人」，選取既有財務旅伴並輸入實付金額。例如總額 1,200 元，甲付 800、乙付 400，三人平均分攤時甲應收 400、乙已平衡、丙應付 400。可增減付款人至該帳本旅伴數（最多 20 人）；同一旅伴不重複、每人金額大於零且合計等於總額才能儲存。手動填寫的部分付款金額不會因總額更動而被覆寫。支出明細及更正歷史均顯示各人的付款金額。

管理者可在任一帳本的「管理旅程」修改已建立的旅伴名稱；新名稱會顯示在舊支出、分攤、還款與成員綁定旁，原旅伴 ID、金額與登入綁定不變。名稱 1–40 字且不可重複，封存旅程須先解除封存。每次更名都記錄舊名與新名。

首頁 `/` 顯示可存取的旅程卡片，可切換進行中／已封存範圍、建立旅程或匯入備份。加入帳本有獨立 `/join` 頁面。每本帳的四個功能各有網址：`/trips/<旅程 ID>/expenses`、`balances`、`team`、`backup`。可直接開啟、重新整理或使用瀏覽器上一頁／下一頁；取得頁面網址不會取得帳本權限。

Sites 以框架路由載入各頁，自架入口使用同一份路由解析及共用介面。帳本頁只讀取網址指定的旅程；封存、未加入、已被移除或不存在時，不會改顯示另一個帳本。登入保留原頁網址；新邀請指向 `/join#join=...`，既有 `/#join=...` 仍可使用。

站內切頁遇到未送出的表單／成員設定會提示保留或放棄；返回快取頁面時會重新同步權限。重新整理及離開分頁使用瀏覽器提供的提示，手機強制關閉或重新登入後不保證保留草稿。新增／匯入成功會開啟該旅程支出頁，其他儲存維持所在頁。

## 分享帳本的步驟

1. 管理者進入指定旅程的「共同記帳」，建立並複製邀請連結。每位受邀者建立一條；連結只在建立當次提供，遺失可撤銷重建。
2. 對方開啟連結、以自己的 ChatGPT 帳號登入，送出申請。一般網站首頁網址只提供入口，不授予任何既有帳本權限。
3. 管理者核對申請者名稱／email，選擇記帳或僅檢視權限，再選擇對應的既有財務旅伴。每位旅伴只能綁定一個有效帳號；不憑同名或 email 自動認領。
4. 核准後對方即可共同記帳；頁面在可見時每 15 秒及重新聚焦時同步。衝突表單保留輸入，需核對最新內容後再送出。

應用程式管理者不等於 Sites 網站編輯者，測試者不需要原始碼或部署權限。撤銷邀請不會移除已核准成員；停止成員權限請使用「移除」。撤銷權限阻擋後續讀取與寫入，無法收回對方已經看到或保存的內容。

## 程式結構

| 部分 | 位置 | 平台依賴 |
| --- | --- | --- |
| 共用畫面 | `app/ledger-app.tsx` | React；呼叫同源 `/api` |
| 金額及分攤 | `lib/domain.mjs` | 無 Sites 依賴 |
| 功能 API／授權 | `lib/api.mjs` | 注入已驗證 subject、repo、objects |
| SQL 存取 | `lib/repository.mjs` | 共用 SQLite SQL |
| 備份 | `lib/backup.mjs` | 版本化契約；不包含登入憑證 |
| Sites 入口 | `app/api/[...path]/route.ts` | 平台登入 headers、D1、R2 |
| 自架入口 | `standalone/server.mjs` | Node HTTP、獨立密碼與 session |
| 自架資料 | `standalone/storage.mjs` | SQLite＋同機收據目錄 |

Sites 身份以 Site ID＋驗證過的 subject 映射至內部 account UUID；不以使用者提供的 email 認領資料。帳務與權限異動使用同一次版本條件更新，避免撤銷權限與記帳競爭時覆寫新權限。自架入口目前仍採單一管理者密碼，匯入後由該管理者管理帳本；旅伴、支出、還款及歷史操作人 ID 保持，收據儲存 ID 重新配置以防覆寫，內容與 SHA-256 保持。匯入清除所有有效帳號綁定與邀請，歷史操作人不能自動登入或認領；自架多人登入及受控帳號重綁仍需下一階段實作。

## Windows 本機執行

需要 Node.js **24 LTS** 與 npm。從本目錄執行（無需 Sites／Cloudflare 登入）：

```powershell
npm ci
node node_modules/vite/bin/vite.js build --config standalone/vite.config.ts
$secret = Read-Host '設定至少 12 字元的本機帳本密碼' -AsSecureString
$env:TRIPLEDGER_PASSWORD = [System.Net.NetworkCredential]::new('', $secret).Password
node standalone/server.mjs
```

開啟 `http://127.0.0.1:4180`，輸入剛設定的密碼。服務停止後，清除啟動用環境變數：

```powershell
Remove-Item Env:TRIPLEDGER_PASSWORD
```

預設只接受本機連線。資料存於 `.data/tripledger.sqlite` 與 `.data/receipts/`；可透過 `DATA_DIR` 指向同一台主機的持久磁碟目錄。每次啟動自動套用未執行的 `drizzle/*.sql` migration。密碼不寫入資料庫；重啟時重新提供同一密碼，已有登入 session 會失效。

不要把 SQLite 檔放在另一台主機的 SMB/NFS 共用磁碟；由單一服務集中存取本機資料。完整自架備份可停服務後複製整個資料目錄，或逐旅程匯出 JSON。

## NAS／Linux 容器的預備入口

本目錄提供 `standalone/Dockerfile`。使用 Node 24 Linux 容器；這次未在實體 NAS 或 Docker 環境驗證。對外提供服務時，要另外完成 HTTPS、網域／入口、持久磁碟與備份。

```sh
docker build -f standalone/Dockerfile -t tripledger-web .
```

啟動需設定 `TRIPLEDGER_PASSWORD`、`HOST=0.0.0.0`、`PORT=4180`、`PUBLIC_ORIGIN=https://你的帳本網域`、`DATA_DIR=/data`，並將 `/data` 掛載到 NAS 的本機磁碟卷。密碼由容器平台的秘密／環境設定提供，不寫入映像或 Git。網域應透過反向代理轉到服務；`PUBLIC_ORIGIN` 必須與外部使用者網址完全一致，代理保留該 Host。HTTPS 模式的 cookie 自動加入 Secure。這一版只有單一管理者帳本，不直接作公開大眾服務。

## 從 Sites 搬出

1. 在 Sites 的每個旅程切到「備份」，下載「此旅程備份」。若內嵌瀏覽器無法下載，可用「檢視完整備份」取得全部 JSON，另存為 UTF-8 `.json` 檔。原始碼備份與帳務備份是兩件事。
2. 啟動獨立服務並登入，在「備份」匯入每個 JSON。既有旅程會拒絕覆蓋。
3. 核對支出、還款、各旅伴餘額與收據；匯入時已核對檔案 checksum 與關聯完整性。
4. 真正切換前停止舊站寫入，重新匯出最終資料，還原到空白目的地，通過核對後再切換使用網址。

匯出固定單一旅程 document 版本，收據不可變且作廢時不刪除，因此同時新增帳目不會混合版本。此首版有嚴格大小限制，採受控 JSON＋base64；未做大量資料的串流、增量、跨旅程同時快照或平台整站匯出。增加上限前必須重新評估 Worker 記憶體、D1 單列大小與備份時間。

## 發布狀態
