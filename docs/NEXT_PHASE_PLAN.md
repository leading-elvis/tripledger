# TripLedger 下一階段實作計畫

更新日期：2026-09-22。第 1 批流程完善及第 3 批多人功能已實作，最新 Sites 版本 6 已發布多頁面介面；依使用者選擇開放網站入口，帳本須登入申請並經核准。目前 19 項自動化測試通過，先前 schema 3 本機還原亦已通過；真實雙帳號及手機實機驗收待完成。精確版本與已完成的測試以 [部署與搬遷驗收](DEPLOYMENT_VALIDATION.md) 為準。

## 下一個交付目標

將已具備多人協作及資料搬遷出口的原型，驗收為可供 3–5 位受邀測試者使用的手機優先記帳工具。暫沿用「旅程／群組分帳」定位，下一步驗證真實帳號共同操作及手機實機流程。Sites 仍為主要託管方式；Windows／NAS 保留搬遷出口。

登入帳號、財務旅伴及帳本權限已分開。任何人可開啟網站入口，但既有帳本只供建立者及核准成員讀取；持邀請連結者登入後申請，管理者核對身份及財務旅伴綁定後授權。一般首頁網址不授予帳本權限。

## 1. 完善單人代記流程（功能已發布）

工作範圍：

- 支出修改／更正：可修正名稱、日期、分類、金額、付款者及分攤，保留更正前資料與時間；已有還款時仍正確重算餘額。
- 旅程名稱修改與封存／取消封存，避免旅程列表隨測試資料增加而難以使用。已發生帳務的幣別不直接切換。
- 支出搜尋及日期、分類篩選；清楚顯示有效、已作廢與更正紀錄。
- 保存失敗或版本衝突時保留表單輸入，提示重新整理及重試；顯示斷線狀態，只有伺服器確認後才顯示已儲存。
- 收據選檔／拍照入口、檔案預覽、超限提示及上傳前壓縮已實作，以配合現有 1 MiB 限制；實機拍照仍列第 2 批驗收。
- 驗證手機與桌機的備份下載、完整備份檢視及匯入；將直接下載／剪貼簿尚未驗證的項目列為待驗收。
- 把目前集中在 `ledger-app.tsx` 的表單、列表、API 狀態拆分，配合新增功能整理，不單獨進行沒有行為成果的大改寫。

驗收結果：11 項測試通過，包含 3 位旅伴、10 筆支出及部分還款的新增、更正、作廢、篩選、餘額計算與備份還原流程；重送、版本衝突、歷史鏈及重新開啟 SQLite 均有驗證。本機 UI 已驗證草稿保留與旅程封存衝突，雲端另以 3 人、1 筆支出、部分還款及 3 筆歷史完成操作與 Windows 還原。這些結果不替代手機實機與完整直接下載驗收。

備份已升級 schema 2，包含封存、分攤方式及更正／旅程歷史；保留 schema 1 匯入相容。實際雲端 schema 2 帳本已還原至獨立 Windows 服務，歷史、餘額、封存狀態及收據一致。此後新增持久欄位仍須同步更新備份及再次還原驗證。

## 2. 手機與桌機的實際使用驗收

- 在可取得的 iPhone Safari、Android Chrome 及桌機瀏覽器驗證登入、鍵盤遮擋、日期／金額輸入、拍照／選檔與下載；沒有設備時保留待驗收，不用模擬寬度代替實機結果。
- 檢查 360／390／768／1280px 代表寬度、表單焦點、觸控範圍及橫向溢位。
- 驗證連點送出、儲存中斷線、session 過期、兩個分頁同時修改同一帳本，確認不丟失輸入、不覆蓋新資料。
- 評估加入主畫面的安裝體驗，先核對 Sites 網址及各瀏覽器支援條件。離線記帳與同步另立階段，避免把安裝入口視為離線能力。

完成條件：列出每個平台的實測結果及未解決項目；至少能以手機完成整條記帳、更正、還款及備份流程。阻礙核心操作的問題先修正，再邀請其他人。

## 3. 受邀多人共同記帳（已實作，真實帳號驗收待完成）

- 分開設計「登入帳號」、「帳本成員資格／權限」與「財務參與者」，保留沒有登入帳號的旅伴。
- 網站公開入口與應用程式內帳本權限分開。已查核正式站首頁匿名回應 200、帳本 API 匿名回應 401；目標測試者的真實 ChatGPT 登入仍待驗收。
- 首批權限定義：管理者管理成員、封存、匯出及帳務更正；記帳成員可新增支出、更正／作廢自己建立的支出；檢視成員唯讀。付款者與實際操作人分開記錄，所有權限由後端驗證；測試者不需要網站編輯權。
- 多人版還款先記為待確認，由收款方確認後才計入餘額；沒有登入帳號的旅伴可由管理者代確認，保留代辦人與時間。已確認、取消及重送都須有明確規則，既有單人版還款保留原有已記錄狀態。
- 邀請 7 天有效、單次使用且可撤銷，登入後提出申請；管理者核准前無法查看帳本。財務旅伴綁定由管理者確認，不憑同名或相同 email 自動合併帳務身份。
- 成員退出後保留歷史帳目與餘額；每次更正／作廢記錄操作者，並處理兩人同時修改的版本衝突。
- 備份擴充成員／財務身份及歷史操作，但不攜帶登入 session、密碼或仍有效的邀請憑證。Windows 還原須重新建立登入與受控帳戶綁定，不自動繼承平台權限。

16 項自動化測試已通過，包含合成帳號的申請／核准、各角色權限、第三者隔離、撤銷與同時寫入、收款方確認／代辦、還款重送及餘額。schema 3 備份保留操作人、成員異動及還款歷程，排除有效帳號綁定與邀請；本機 D1/R2 → 全新 Windows Node/SQLite 還原、收據比對及重啟持久化已通過，仍相容 schema 1、2。

真實環境完成條件：至少 2 個獨立 ChatGPT 帳號加入同一帳本、共同新增及更正帳目，雙方重整後一致；未加入的第 3 個帳號無法讀取帳務、收據或備份，唯讀者不能寫入，撤銷權限立即生效。未授權的支出更正與還款確認必須拒絕；還款確認／取消／重送後餘額仍正確。正式雲端 schema 3 多人備份還原仍待驗收，不以本機合成帳號測試代替。

網站入口已依使用者明確選擇公開；不用逐一加入 Sites email allowlist。所有帳本讀寫仍由後端驗證帳本成員權限，測試者不需要 Sites 編輯權。

## 4. 小範圍試用與後續功能排序

建議以 3–5 人、一趟旅程或約一週為試用批次，記錄新增一筆帳目的步驟、常見誤操作、分攤是否易懂、收據及備份是否順利。問題依「金額／資料錯誤 → 無法完成操作 → 操作不順 → 外觀」排序。

下一批功能以試用結果選擇，初步候選順序為：

1. 百分比／份數／品項分攤，補齊舊版常用情境。
2. 外幣支出與歷史匯率快照、分類統計。
3. OCR／發票解析及人工確認，先量測辨識品質與外部服務用量。

公開註冊、完整離線同步與付費訂閱另外規劃；現在持續保留身份、帳本權限、功能權益、用量與付款整合的邊界。付費實作前再確認當時的平台條件與服務規範。

## 每批共同的交付要求

- 在獨立分支保留變更及可回復版本，更新 PR 與部署來源對照。
- 執行與變更相關的帳務／權限／備份測試、型別檢查及 Sites／standalone 建置。
- 新資料結構通過既有備份相容及新版 Windows 還原驗證。
- 保持內測無購買、升級及廣告入口。涉及外部服務時先記錄用量與成本來源，不假設永久免費。
- 在具備原 GCP 帳務與資源讀取權限時，盤點是否仍有計費資源，提出可停用清單；本計畫不刪除或停用既有服務。

## 現在的起點

下一批先用真實雙 ChatGPT 帳號完成邀請申請、核准、共同記帳及收款確認，再補上 iPhone／Android 實機拍照、下載、輸入與登入情境。通過後進行 3–5 人小範圍試用。草稿目前只在開啟頁面中保留，重新登入或重整後不保證保留；離線持久化／同步、自架多人登入與付費功能尚未實作。
